# cdev

*[English README](README.md)*

`cdev` は明示的に呼び出す Codex のマルチエージェントワークフローで、
コーディングタスクを実装します。ルートエージェントが、継続利用する
producer と独立 reviewer の2エージェントを調整します。

## 呼び出し例

~~~text
$cdev:coding 要求された機能を実装し、リポジトリの検証を実行して、
変更はコミットせずに残してください。
~~~

スコープ、必須の検証、コミットの可否、変更してはいけないファイルなど、
重要な制約は依頼に含めてください。

- `--review-rounds N` は設計・コードの各 producer/reviewer ループ上限です。
  デフォルトは5回、範囲は1〜10回です。
- `--qa-attempts N` は QA/修正ループ上限で、デフォルトは5回、範囲は1〜10回です。
- `--commit` は QA 成功後に今回の変更をコミットします。省略時はコミットしません。
- `--output {dir}` は設計書の出力先ディレクトリです。省略時は
  `.codex/tmp/cdev-coding-{timestamp}-design/` を使います。相対パスは worktree 使用時も起動元リポジトリの
  ルートから解決します。リポジトリのルート、ソースを含むディレクトリ、今回削除する
  作業用ディレクトリ自身やその配下は指定できません。

設計書 `{design_dir}/design.md` は実行後も残り、最終報告にパスを表示します。
作業用の `.codex/tmp/cdev-coding-{timestamp}/` は実行後に削除します。
`--commit` は `.codex/tmp/` と設計書の出力先をステージ対象から除外します。

## ワークフロー

1. リポジトリ指示とタスクスコープを確認し、指定された作業ツリーを準備します。
2. 継続利用する producer と reviewer を1つずつ起動します。
3. チーム分析を行い、設計を作成します。
4. ゲートを通過するまで設計と設計レビューを反復します。
5. 設計を実装し、コメントとコードをレビューして指摘へ対応します。
6. リポジトリ固有の検証と独立 QA ゲートを実行します。
7. ユーザーが明示的に依頼した場合だけコミットします。
8. 実行中の teammate とその子孫を `collaboration.interrupt_agent` で停止してから、scratch と
   workflow 所有の worktree を削除します。idle の teammate に shutdown の応答待ちは不要です。
   停止失敗は報告し、関連するパスを保持します。

後続フェーズでも同じ2つの子エージェントを再開し、文脈を維持しつつ
ルートワークフロー用に1スロットを空けます。スロットが少ない場合は
作業をキューに入れます。

設計の作成・改訂と設計レビューは [発散パターン防止ルール](rules/divergence.md) に従います。
未確定の仕様・不変条件、個別ケースへの対処では閉じきれない問題クラス、裁定されていない
要求の相反、既存設計との不整合を設計段階で扱います。reviewer は該当箇所を Major 以上として
指摘します。設計が明記した受け入れ範囲の外の反例は指摘せず、その範囲ではタスクを
満たせない場合に限り、範囲自体を指摘します。

## 安全性と出力

- `--worktree` がない場合は、ユーザー変更を出力と誤認しないよう、開始時にクリーンな
  Git worktree が必要です。この確認では `.codex/tmp/`、`.codex/worktrees/` と明示された `--output` の
  指定先配下を除外するため、過去の設計書は次の実行を妨げません。
- プロジェクトとユーザーの Codex エージェントプロファイルを役割プロンプトに
  利用でき、同梱の参照プロファイルをフォールバックにします。
- 中間ファイルは `.codex/tmp/` 以下だけに出力します。
- 対象リポジトリの `AGENTS.md`、フォーマット、ビルド、テスト指示に従います。

## 必要条件

- Git リポジトリ
- Python 3.11 以降
- Codex のコラボレーションツール
- プロジェクト固有のビルド・テスト依存関係

## worktree での実行

`$cdev:coding --worktree[=branch]` は `.codex/worktrees/` に別 checkout を作り、
`--commit` も有効にします。branch が既存ならその tip、未作成なら現在の HEAD から開始し、
省略時は `cdev-coding-{timestamp}` を新規作成します。別 checkout で使用中の branch は
指定できません。起動元の作業ツリーは未 commit の変更があっても利用できますが、その変更は
worktree へコピーされません。

source の相対パスは worktree 基準です。起動元内の絶対パスは読み取り専用で、
自動的に worktree 内へ置き換えません。文書と一時ファイルは起動元へ保存し、
相対の出力先も起動元基準で解決します。worktree 内を永続文書の出力先には指定できません。
project の Codex profile と `.codex/rules/` も起動元から読みます。

終了時は worktree を削除して branch を残します。未 commit 変更や削除を妨げる状態があれば
worktree を保持し、そのパスを報告します。削除時は内部の ignored file も削除されます。
branch の merge や push は行いません。

Git が無視する依存関係・仮想環境・生成物・`.env` と submodule の内容は worktree に
引き継がれません。新規 checkout で検証できる環境が必要です。configure は build stage の
開始時だけに実行されるため、先に動く formatter や build なしの test の準備には使えません。
不足した前提条件だけによる失敗では source 修正を止め、環境原因として報告します。
コード原因が混在する場合は、その部分だけを修正対象にします。
QA が失敗した場合はコミットせず、変更を worktree に残します。
このスキルはリポジトリルートから起動してください。
